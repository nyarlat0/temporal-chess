# Temporal Chess

Шахматы с инверсией фигур в духе «Довода», с локальной игрой вдвоём, ботом TempFish и сетевыми комнатами.
История хранится как мировые линии фигур; доска — их срез по времени.

## TempFish

В правой панели раскройте **TempFish**, включите «Играть против TempFish» и
выберите свою сторону. Эти же настройки доступны при создании новой партии.
Доски всегда ориентированы к человеку; бот показывает ход обычной анимацией.

Дискретный ползунок задаёт бюджет: **50, 200, 800, 3000 или 10000 узлов**.
Узел — попытка применить команду к позиции. Бюджет ограничивает объём перебора,
а не секунды: стоимость пересчёта истории у разных команд различается.
TempFish использует итеративное углубление и альфа-бета-поиск; панель показывает
расход узлов и последнюю полностью законченную глубину. В глубину входят все
действия, включая бесплатные протаскивания и продолжение расчёта. После исчерпания
бюджета используется последняя законченная итерация (либо проверенный частичный
результат, если не закончена даже первая). Максимальная глубина — 6 действий.

«Ход сейчас» заканчивает поиск на уже рассчитанном результате. «Пауза бота»
приостанавливает игру с ним. Отмена хода также ставит бота на паузу, чтобы он
сразу не повторил отменённый ход; для продолжения снимите паузу. Можно включить
бота для импортированной позиции. Бот не действует в сетевых комнатах.

Это начальная версия: оценка учитывает материал по мировым линиям (без повторного
учёта одной фигуры на разных досках), положение фигур, активные резервы и исход
партии. Ходы проверяются обычным движком, включая инверсию, продвижение по истории,
отказ от реакций, продолжение расчёта и поражение от парадокса. Нативный поиск
выполняется в отдельном вычислительном потоке; браузерный — порциями между кадрами.
Один вызов движка остаётся неделимым и в сложной истории может занять заметное время.

Поиск находится в отдельном крейте `crates/tempfish`, без зависимости от Bevy.
Проверки поиска: `cargo test -p tempfish`.

## Мультиплеер и браузер

Язык интерфейса переключается в правой панели: русский или английский. При первом
открытии сайта выбирается первый поддерживаемый язык из предпочтений браузера
(иначе английский). Ручной выбор сохраняется в `localStorage` под ключом
`temporal-chess.language` и имеет приоритет при следующем открытии. Если хранилище
недоступно, переключение работает до закрытия страницы. Проверка определения
языка без запуска браузера: `node tools/test-web-language.cjs`.

В правой панели откройте «Играть по сети»: создайте комнату, выберите сторону и
передайте код сопернику. После обрыва связи клиент переподключается и восстанавливает
серверную историю. Сервер не запускает движок: при подключении сверяются хэши
его ревизий, а команды записываются только после автоматического подтверждения
обоими клиентами. Локальная игра остаётся доступна.

- [Запуск сервера и PostgreSQL](crates/server/README.md)
- [Оптимизированная WASM-сборка и размещение через Caddy](deploy/README.md)

```sh
# Нативный сервер (нужен DATABASE_URL):
cargo run -p temporal-chess-server --release
# Готовый браузерный пакет в dist/web:
tools/build-web.sh
```

## Запуск игры

```sh
cargo run -p temporal-chess-bevy
```

Нужны Rust/Cargo и графическая сессия с поддерживаемым Bevy GPU. На Linux
включены Wayland и X11. Первая сборка компилирует графические зависимости.
Шрифт интерфейса и классические SVG-фигуры Cburnett встроены в бинарник; запуск не зависит от рабочей
директории. Для автоматической проверки запуска окна: `cargo run -p
temporal-chess-bevy -- --smoke-test` (закрывается через 180 кадров).

- Новейшая доска находится сверху. Колесо прокручивает ленту, **ПКМ + колесо**
  меняет масштаб, сохраняя выделение. Сброс масштаба — кнопка на правой панели.
  Переходы к началу/концу истории находятся на правой панели. Рядом с линией
  времени, слева от неё по центру окна, вертикально закреплены «Предыдущая активная»
  и «Следующая активная»: они плавно переходят между досками с доступными фигурами
  текущего игрока. Список зациклен; колесо прерывает автоматическую прокрутку.
- В локальной игре ориентация следует очереди; при смене стороны доски плавно
  затухают и появляются развёрнутыми. В сети ориентация постоянна: ваш цвет снизу.
  Перед ходом соперника камера плавно переходит к исходной доске, затем показывает
  ход и возвращается к вашей активной доске. Управление и отображение новой очереди
  включаются после завершения этой последовательности.
- ЛКМ выбирает активную фигуру, затем клетку **на той же доске**.
  Клик по чужой или неактивной фигуре ничего не меняет, если это не доступное
  взятие. В инспекции можно выбирать любые фигуры. Движок сам
  применяет ход на соседнем времени. Выбор и смена направления не двигают
  доски на экране. После успешного хода фигура плавно перемещается, а доска
  наезжает на соседнюю по направлению хода. Одновременно проигрываются все
  перемещения через эту временную границу, включая встречные в обратном
  направлении, рокировку и превращение. Затем лента плавно переходит к первой
  сверху активной доске текущего игрока.
- СКМ переключает направление выбранного хода; начальное направление совпадает
  с ориентацией фигуры. Будущее подсвечено розовым, прошлое — тёмно-карминовым:
  точки на свободных клетках. Доступные взятия отмечены красным ореолом фигуры
  с плавным затуханием прозрачности; наведение усиливает подсветку. Последний
  сыгранный ход на каждой исходной доске отмечается стрелкой от начала к концу:
  розовой в будущее, карминовой в прошлое. На конечной доске отметки этого хода нет;
  видимый шах — красным контуром короля, угроза только из будущего — розоватым.
- ПКМ в любом месте или Esc снимает выделение. Белые инвертированные фигуры
  голубоватые с синим контуром, чёрные — тёмно-карминовые; толщина линий обычная.
  На досках до последней в истории ordinary отмечается зелёной подсветкой клетки.
  Реакции отмечены значками над фигурой: жёлтый глаз — новая информация,
  оранжевая перечёркнутая стрелка вверх — отменённый ход (без дополнительного глаза).
  Взятия и шах сохраняют свои контуры. Активные доски выделены толстой
  закруглённой рамкой своего цвета — белого либо чёрного.
- Кольцо с точкой на тех же координатах другой доски позволяет
  бесплатно продвинуть фигуру на **любое доступное время** по её ориентации,
  в пределах существующей истории. Просто отказаться от хода на месте нельзя:
  время назначения должно отличаться от исходного. Любая другая живая фигура
  на той же клетке любой промежуточной или конечной доски блокирует ожидание.
  Это проверка команды ожидания, а не постоянно валидируемый ход.
- После отмены возврата из прошлого инвертированная линия продолжается до `t=0`
  у белых или `t=1` у чёрных; ordinary-активность даётся только этому концу.
  В точке отмены остаётся реакция, а столкновения продолжения разрешаются обычно.
- Отменённый ход останавливает просчёт перед столкновениями, отменой других ходов,
  изменением жизни фигур или появлением новых реакций, включая реакции противника.
  Без вторичных последствий доски строятся дальше автоматически.
  «Продолжить просчёт» / C разрешает
  дальнейшее согласование до следующей такой остановки либо конца истории.
  Очередь не расходуется. Предоски полупрозрачны и сохраняют наложившиеся фигуры.
- «Инспекция» / I, затем фигура: все поля состояния, мировая линия, причинные
  разрывы и записанные ходы в боковой панели. При наложении можно выбрать
  конкретное воплощение. Инспекция работает и на предосках.

Кнопки действий обозначены векторными иконками; название появляется после
0,7 секунды неподвижного наведения. Правая панель показывает очередь хода,
число активных досок, состояние просчёта, масштаб, выбранную фигуру и направление
её хода. Там же находятся отмена (Ctrl+Z), копирование записи, загрузка, новая
партия, история и инспекция. Нажатие на запись в истории переходит к её доске.
Верхней и нижней панелей нет. Время подписано числами слева на линии; лишних
пустых строк в конце ленты нет.

Направление выбранного хода на панели подписано без цвета; соседняя кнопка
показывает стрелку вверх или вниз. История имеет вид
`1. [иконка фигуры] (d2, 0) -> (d4, 1)`, без раскрашивания текста. Уменьшенная
SVG-фигура сохраняет вид и цвет участника команды; инверсия отражает направление
этого хода. Данные иконки фиксируются при записи и восстанавливаются при импорте.

Красный ореол взятия показывается только если прогноз движка подтверждает гибель
цели. Если цель выживает, а выбранная фигура погибает, вместо ореола справа
сверху от противника появляется красный череп. Сам ход остаётся доступен.
Прогноз не изменяет партию; нерешённый конфликт или парадокс не выдаётся за
подтверждённое взятие или гибель.

Иконка копирования на правой панели помещает полную запись в буфер обмена;
галочка на две секунды подтверждает действие.
**Загрузить → вставить текст (Ctrl+V) → подтвердить галочкой**
разыгрывает запись с начальной позиции и позволяет продолжить партию.
Загрузка выполняется в фоне; ошибка показывает строку и сохраняет текущую партию.
Текст можно сохранить в любом редакторе. Диалог сохранения на диск, сеть
и компьютерный соперник пока отсутствуют.

Формат `NOLAN-CHESS 1` хранит команды в порядке их выполнения, включая
впоследствии отменённые ходы, инверсии, продвижение фигур и продолжение просчёта.
Это собственный формат игры, не PGN. Например, начало `e4 e5`:

```text
NOLAN-CHESS 1
move 0 12:0:0 e2 e4 + normal
move 1 28:1:0 e7 e5 + normal
```

В строке `move`: время, идентификатор `wid:fut_seen:loop_turn`, исходная клетка,
цель, направление `+`/`-`, эффект (`normal`, `O-O`, `O-O-O`, `ep:d5`, `=Q/R/B/N`).
`advance <время> <идентификатор> <клетка> <время назначения>` продвигает фигуру;
`continue` подтверждает текущую остановку просчёта;
`decline` деактивирует реакции текущего игрока и передаёт ход, если у него
есть реакции и нет обычных активных фигур. Допускаются пустые строки
и комментарии `#`. Импорт принимает до 2 МиБ и 10000 команд.

Классическая доска использует бежевые и коричневые клетки, фигуры — набор
[Cburnett из Lichess](https://github.com/lichess-org/lila/tree/master/public/piece/cburnett)
авторства Colin M. L. Burnett (GPL-2.0+, лицензия рядом с SVG). Для ленты
использован принцип временной оси и рамок досок из 5D Chess; для ходов — точки
и контурные подсветки шахматных сайтов.

## Правила

Направление времени выбирается для каждого хода вместе с пространственным
перемещением. Игрок может выбрать любой доступный обычный или реакционный ход;
обязательного порядка досок нет. После пространственного хода очередь переходит
сопернику; при отсутствии действий она может автоматически вернуться.
Ход на времени `t` гасит реакции своей стороны на досках `<= t`, сохраняя
обычную доступность вне разыгранного слота хода.
Перед применением хода текущая информация своей стороны на этих досках добавляется
в долгосрочную память состояний. Память только растёт; информация на досках `> t`
не фиксируется. «Не реагировать» фиксирует текущую информацию на всех своих досках.
После протаскивания актуальная информация пройденных состояний фигуры добавляется
в их память, чтобы само ожидание не давало ей инфо-реакцию. Память других фигур
не меняется. Продолжение расчёта само по себе информацию не фиксирует.

Инфо-реакции вычисляются заново из разницы текущего обзора и долгосрочной памяти:
исчезнувшая цель больше не поддерживает реакцию. Для каждого полного ID цели
`(wid, fut_seen, loop_turn)` реагирует только первое подходящее состояние каждой
наблюдающей мировой линии, в её причинном порядке (не по минимальному времени доски).
Состояния с собственным записанным ходом, отменой хода или ordinary-активностью
не получают дополнительной инфо-реакции.
Если остались только реакции, кнопка «Не реагировать» позволяет отказаться
от них всех и передать ход. Это действие сохраняется в журнале и при импорте;
оно доступно и в сетевой игре. При наличии обычной активной фигуры отказ недоступен.

**Состояние реализации:** работают ходы в прошлое, возвращение в будущее,
вложенные петли и замена прежнего хода. При повороте во времени прежнее
продолжение заменяется новым участком мировой линии.
Уход с последней доски не оставляет копию фигуры на новой будущей доске.

Геометрия хода и занятость клеток вперёд проверяются на `t + 1` (на `t`,
только если будущей доски ещё нет), назад — на `t - 1`. Безопасность короля
для хода вперёд проверяется после пространственного перемещения в позиции
исходной доски `t`: атакующая фигура, появившаяся только в будущем, не должна
запрещать этот ход или отменять его при пересчёте истории. Для хода назад
безопасность проверяется на прошлой доске назначения. Информация для реакций сканируется только на текущей доске фигуры:
появление доступной цели на соседней доске не активирует её в прошлом. Обычные ходы, взятия, рокировка, en passant, превращение,
отмена зависимых ходов и восстановление фигур покрыты тестами.
Рокировка остаётся только вперёд; ходы назад доступны при `t > 1`.

Если активные фигуры не имеют ни допустимого хода, ни продвижения по истории,
под шахом фиксируется мат, без шаха — пат. Мат и пат откладываются, пока
у противника остаются обычные долги в прошлом. Например,
`d4 d5 Nf3 e6 g3 Bb4` заканчивается матом белым без автоматической передачи хода.
Фактическая гибель любой инкарнации короля также означает поражение.
Цикл согласования истории означает поражение автора команды. Пат фиксируется
только при наличии активных фигур, отсутствии доступных действий, угроз королю и обычных долгов
противника в прошлом; иначе игрок ожидает, пока противник изменяет историю.
Если активных фигур вообще нет, очередь передаётся стороне, у которой они есть.
Если их нет у обеих сторон, игра ожидает без автоматического пата.
Если король уже под видимым шахом на исходной доске `t`, запрещён ход с этой
доски, после которого активный противник на `t + 1` может взять короля ходом
в прошлое или будущее. Заслон только в будущем или уход короля не защищает
его прежнее состояние от обратного взятия. Угрозы, исходящие только из будущего,
не включают этот запрет: они отмечаются розоватым контуром короля. Ограничение
не переносится на ходы с других досок истории. Обычная проверка безопасности
короля использует исходную позицию для хода вперёд и прошлую доску назначения
для хода назад; это правило одинаково для новых и уже записанных ходов.
Фигуры с обычными правами можно бесплатно продвигать в текущем направлении
времени, только на другую доску существующей истории.

## Использование

Workspace разделён на независимый крейт `crates/engine` (библиотека
`temporal_chess_engine`, без внешних зависимостей) и `crates/bevy_front` (приложение
`temporal-chess-bevy`, Bevy + egui). Приложение использует только публичный API
движка; отображение не меняет мировые линии напрямую.

```rust
use temporal_chess_engine::engine::Engine;
use temporal_chess_engine::model::{Color, Sq, TimeDirection};

let mut game = Engine::default(); // Сразу содержит доску и индексы.
let pawn = game.move_sources()
    .find(|piece| piece.t == 0 && piece.sq == Sq(4, 1))
    .expect("white e-pawn");
let mv = game.possible_moves(pawn.origin, pawn.age)?
    .into_iter()
    .find(|mv| mv.sq == Sq(4, 3) && mv.direction == TimeDirection::Future)
    .expect("e2-e4");

game.apply_new_mv(mv)?; // Ход, согласование истории и смена очереди атомарны.
assert_eq!(game.turn(), Color::Black);
assert_eq!(game.board(1).unwrap().get_piece(4, 3).unwrap().origin, pawn.origin);

let restored = Engine::from_history(game.history().clone(), game.turn())?;
assert_eq!(restored, game);
# Ok::<(), temporal_chess_engine::engine::EngineErr>(())
```

`move_sources()` перечисляет доступные состояния фигур на всех досках для
текущего игрока. Для сценариев и тестов есть `State::new` и
`Engine::from_worldlines`; после построения движка история доступна только на чтение.

`record::GameRecord::apply(&mut engine, Command)` выполняет команду и добавляет
её в журнал только при успехе; `to_text()` экспортирует запись,
`GameRecord::load(text)` возвращает восстановленные `(Engine, GameRecord)`.
Журнал предназначен для стандартной начальной позиции с интерактивным просчётом.

Новые команды и запросы:

- `skip_ordinary(source: PieceAt, to_t)` — бесплатное ожидание выбранной фигуры.
  Не меняет её клетку, направление и флаг `moved`, не расходует права других
  фигур. `to_t == source.t` отклоняется без изменения состояния.
- `checks(color)` — обычные и инвертированные угрозы королям, с указанием `PieceAt`.
- `status()` — `Ongoing`, `Waiting` или `Finished`; `outcome()` — победа
  (`Checkmate` / `KingCaptured` / `Paradox`) либо `Stalemate`.
- `with_interactive_calculation()` — включить остановку согласования у первой
  своей фигуры с отменённым ходом, изменённые состояния которой непосредственно
  вызывают конфликт, отмену другого хода, восстановление фигуры или новую реакцию.
  Независимые изменения не вызывают остановку на этой фигуре.
  Приложение включает этот режим; обычный
  `Engine::default()` по-прежнему согласует всю историю сразу.
- `calculation_status()` / `continue_calculation()` — состояние просчёта и его
  бесплатное продолжение. Предоски после остановки доступны через `preboard`,
  а `board` возвращает для них `None`. Из них нельзя ходить до просчёта.
- `can_decline_reactions()` / `decline_reactions()` — проверить доступность
  отказа от всех реакций и выполнить его с передачей хода.
- `move_capture_target(Move)` — фигура-цель на фактической доске назначения,
  включая взятие на проходе и восстановленные цели заменяемого хода.
- `timeline_times()` / `piece_state(PieceAt)` — времена истории и стабильный
  поиск состояния для инспектора; `possible_skips(PieceAt)` — цели ожидания.

После каждой команды следует проверять `outcome()` и `turn()`. Поражение от
парадокса возвращает `Ok(())`: результат записывается, а доски сохраняются
в последнем согласованном состоянии. После завершения команды отклоняются
с `EngineErr::GameOver`. Результат и ожидание входят в снимок `History`.

Подробнее: [модель, инварианты и дальнейшая разработка](docs/architecture.md).

## Проверка

```sh
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
# Только движок, без сборки Bevy:
cargo test -p temporal_chess_engine
```

Внешних зависимостей у библиотеки нет. Пример выше также запускается как doctest.

Подробные правила [отмены и замены ходов](docs/move-history.md), включая петли,
сохранённое будущее и различие журнала команд и истории движка.

## Настройки правил

Причинные разрывы удалены: поворот в любую сторону всегда удаляет прежнее
продолжение мировой линии. Два независимых флажка в окне новой партии и при
создании сетевой комнаты по умолчанию выключены:

- **Цепная инфоактивация / Chain info-activation**: новая цель активирует каждое подходящее состояние
  мировой линии, а не только первое в причинном порядке. Полный ID цели
  `(wid, fut_seen, loop_turn)` и динамический пересчёт информации сохраняются.
- **Реагировать один раз / React once**: ход сбрасывает свои реакции
  на всех досках, включая реакции отменённых ходов, и фиксирует текущую информацию
  в аддитивной памяти состояний. Сброс и фиксация выполняются перед применением
  хода, как в стандартном режиме; новые последствия пересчёта остаются новыми
  реакциями. Обычная активность не сбрасывается.

В середине партии правила не переключаются. Настройки сохраняются при экспорте,
импорте, отмене хода и сетевом переподключении. Новый формат записи:

```text
NOLAN-CHESS 3
chain_info_activation off
global_reaction_reset off
move 0 12:0:0 e2 e4 + normal
```

Записи `NOLAN-CHESS 1` без настроек и `NOLAN-CHESS 2` с `causal_gaps off`
импортируются с обоими флажками выключенными. Записи с `causal_gaps on`
отклоняются с пояснением об удалённом режиме. Старые сетевые комнаты с разрывами
также недоступны для продолжения; их журналы остаются в базе.
Для сетевого режима обновляются и клиент, и сервер (версия протокола 4).
Миграция 0004 добавляет независимые настройки комнат.
