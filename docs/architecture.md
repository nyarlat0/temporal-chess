# Модель и границы движка

## Правила, на которых основана архитектура

1. У фигуры есть собственный возраст `age` и координата времени доски `t`.
   Возраст увеличивается вдоль мировой линии, даже когда `t` уменьшается.
2. Направление задаётся каждым ходом. Это не отдельная команда инверсии.
   Пространственное перемещение связано с переходом на соседнюю доску.
3. Доступные ходы делятся на обычные и реакционные. Ни один ход или момент
   времени не является обязательным. Игрок выбирает доступное состояние фигуры.
4. После успешного хода игроки меняются. Ошибка не меняет ни историю, ни очередь.
5. Собственный ход на доске `t` гасит собственные реакции на досках `<= t`.
   Реакции в более позднем времени и обычная доступность на других досках
   сохраняются. Реакции противника этот шаг не гасит.
6. Разыгрывание слота `(t, fut_seen, loop_turn)` расходует доступность фигур
   этого причинного порядка на данной доске. Реакция может заменить прежний
   ход другой фигуры в том же слоте.

Из прежнего прототипа сохранены привязка цвета к чётности `t`, выбор направления
в прошлое при `t > 1`, понятия `fut_seen` / `loop_turn` и правила столкновений.
Эти правила не следует смешивать с отсутствующим требованием «сначала сыграть
на самой ранней доске».

## Слои

| Слой | Ответственность |
| --- | --- |
| `model` | Координаты, идентификаторы, `State`, `Worldline`, `CausalGap`, `PieceView`, права хода, направление и вид хода. Не зависит от `Engine`. |
| `pieces` | Геометрия ходов фигур и единая исходная расстановка. |
| `board` | Одномоментный пространственный срез, атаки и сведения о доступных целях. |
| `History` | Мировые линии, записи разыгранных слотов и их целей, последнее время доски `horizon`. Вместе с `Engine::turn` составляет сохраняемое состояние. |
| `Projection` | Пересоздаваемые `PreBoard`, `Board` и индекс состояний. Не является частью истории. |
| `engine/collision_rules` | Чистый расчёт последствий столкновения: кого погубить или чей ход отменить. |
| `engine/temporal` | Вставка и замена причинных участков, сохранение будущего и замыкание петель. |
| `Engine` | Проверка команды, изменение истории, согласование последствий и публикация результата. |

`Board` имеет закрытый индекс занятости. Добавление и удаление фигур обновляют
его вместе с массивом фигур. `PreBoard` допускает несколько состояний на одной
клетке: это временное пересечение, которое должен разрешить движок. Раскладка
всех пространственных массивов едина: `[x][y]`.

Внешний код получает историю и доски движка через неизменяемые ссылки. Нельзя
изменить `worldlines`, забыв обновить доски. Собственную позицию сначала строят
как данные и передают в проверяющий конструктор `Engine::from_worldlines`.
Для восстановления снимка используются `history().clone()` и `turn()`.
Сериализация пока не добавлена.

## Идентичность во времени

| Значение | Что обозначает |
| --- | --- |
| `wid` / `origin` | Исходная фигура, то есть номер мировой линии. |
| `ShortPieceId { wid, age }` | Конкретное место в текущем массиве состояний. После вставки или удаления ранних состояний индекс может измениться. |
| `PieceId { wid, fut_seen, loop_turn }` | Причинная версия фигуры. Она может присутствовать на нескольких досках обратного участка. |
| `PieceAt { piece, t }` | Конкретное появление причинной версии на доске. Ключ поиска источника хода. |
| `MoveId { t, fut_seen, loop_turn }` | Общий слот хода для фигур одного причинного порядка. Намеренно не содержит `wid`. |

Например, состояния на временах `4 -> 3 -> 2` могут иметь одинаковый `PieceId`,
но разные `age`. Индекс только по `PieceId` затирал ранние состояния поздними.
Теперь поиск хода использует `PieceAt`, а одинаковые `PieceAt` внутри загруженной
истории считаются ошибкой. У нескольких возрастов одной фигуры на одной доске
должны различаться причинные версии.

`fut_seen` — максимальное увиденное время. `loop_turn` различает проходы внутри
петли. В `State::step(direction)` каждая смена ориентации увеличивает счётчик
на один. При повороте в прошлое время исходной доски добавляется в стек
`loop_pivots`. При движении вперёд счётчик уменьшается на два за каждую
пересечённую точку: строго при `новое t > pivot`, не на самой точке.
Вложенные и совпадающие повороты обрабатываются тем же стеком.
`State::prolongate` — пассивный шаг в текущем направлении.
Переполнение времени или счётчика и уход ниже `t = 0` возвращают `None`,
а не создают повторное состояние или обнулённый счётчик.

## Мировая линия и долг причинности

`Worldline` хранит состояния в субъективном причинном порядке, **не в порядке
времён досок**. Внутри связанного участка соседние состояния разделены одним
тактом. При незавершённой петле линия содержит явный разрыв `CausalGap`:

```text
До инверсии:       0 → 1 → 2 → 3 → 4 → 5 → 6
После хода 4 → 3:  0 → 1 → 2 → 3 → 4 → 3 → 2  ⋯  5 → 6
После возврата:    0 → 1 → 2 → 3 → 4 → 3 → 2 → 3 → 4 → 5 → 6
```

После активного хода создаётся также пассивное состояние на следующей доске
своего цвета, если она не выходит за границы истории. Поэтому ход из `4` в `3`
даёт доступное инвертированное состояние на `2`.

Разрыв хранит устойчивые ключи `entry` (вход), `after` (текущий конец участка)
и `resume` (начало сохранённого продолжения, либо `None`). Возрасты этих состояний
могут сдвигаться при вставках. Вложенная петля может иметь собственный разрыв.

Вставка, перемещение и распространение гибели не переходят через разрыв в
сохранённое будущее. Его ходы не перевалидируются, сведения о целях не
пересчитываются, пока причинность не восстановлена. При достижении `resume`
с ожидаемым `(t, fut_seen, loop_turn)` движок присоединяет уже существующее
состояние вместо создания копии. Затем обычное согласование обновляет позиции
и отменяет недопустимые последующие ходы. Сохранённые доски остаются игровыми:
это защита от распространения незавершённой петли, а не запрет явно ходить там.

Замена хода в прошлое ходом вперёд удаляет прежнюю экскурсию и записи ходов,
источники которых исчезли. Повторный ход в прошлое изменяет пространственный
участок существующей петли. Отмена поворота восстанавливает исходную ориентацию.

При уходе с последней доски обычное продление этой фигуры пропускается:
на новой будущей доске её копии нет. `History::horizon()` сохраняет последнее
время даже у пустой доски. Снимок `History` включает разрывы; загружать историю
петли как простой `Vec<State>` с пропущенным участком нельзя.

## Ходы и доступность

`Move` содержит источник, клетку назначения, `TimeDirection` и `MoveEffect`.
Варианты эффекта: обычное перемещение, рокировка, en passant, превращение.
Несовместимые комбинации эффектов нельзя задать. `Promotion` содержит только
коня, слона, ладью и ферзя. Обычное взятие определяется занятостью клетки.

`MoveRights` одинаково используется в полной записи `State` и в её `PieceView`:

- `ordinary` — обычная доступность;
- `new_information` — реакция на появление новых доступных целей;
- `cancelled_move` — реакция на отмену прежнего хода.

Причины независимы. `expire_reactions` очищает две последние, не меняя
`ordinary`. Список целей хранится как множество `BTreeSet<PieceId>`: сравнение
не зависит от порядка, одна цель не учитывается несколько раз. Появление новой
цели даёт реакцию; одно лишь исчезновение цели её не создаёт.

`move_sources()` возвращает все доступные состояния текущей стороны.
`possible_moves(wid, age)` рассчитывает пространственных кандидатов для
конкретного состояния, независимо от очереди и прав доступа. Это нужно также
для повторной проверки уже записанных ходов. Командный метод `apply_new_mv`
дополнительно проверяет сторону и права, применяет переход и согласует историю.

Для каждого направления используется собственная доска назначения: `t + 1`
для будущего (при отсутствии — `t`), `t - 1` для прошлого. Преграды, взятия
и безопасность королей проверяются именно на ней. Из временной проверочной
доски убирается ожидаемое следующее состояние ходящей фигуры, но не произвольная
другая её инкарнация. Историческое взятие повторно проверяется с учётом
запомненной цели, иначе погибшая пешка сделала бы собственное взятие незаконным.
Эта же проверка доступных ходов используется для обнаружения новых целей
реакции. `Board::calc_info` остаётся пространственным вспомогательным методом;
движок вычисляет временные сведения отдельно.

## Изменение и согласование истории

Команда исполняется на копии `Engine`. После изменения истории движок повторяет:

1. Построение всех временных срезов и индекса появлений из мировых линий.
2. Поиск пересечений в порядке времени. Для одного пересечения отслеживается
   исходное столкновение и применяется рассчитанный набор последствий.
3. Проверку записанных ходов в порядке `MoveId`. Один недопустимый ход отменяется.
4. Восстановление одной мёртвой части линии, если исчезла её причина захвата.

После любого изменения цикл начинается заново. Поэтому следующий конфликт
или ход не проверяется по доске, собранной до отмены предыдущего хода.
Проверяются все представленные времена, а не префикс до условного обязательного
хода. Порядок `BTreeMap` делает выбор следующего конфликта и хода воспроизводимым.

Когда история перестаёт меняться, обновляется информация текущего игрока,
и права проецируются обратно на доски. Если сама новая команда была отменена
при согласовании, команда возвращает ошибку. Только успешный результат целиком
заменяет состояние исходного движка.

Циклы определяются сравнением полных `History`, включая мёртвые состояния
и журнал ходов. Сравнивать только живые фигуры на доске было недостаточно.
Копирование всей истории выбрано для простоты проверки прототипа. Оно и хранение
снимков на каждой итерации могут быть дорогими для длинных партий; журнал
обратимых изменений и инкрементальные проекции можно добавить позже, сохраняя
атомарный контракт внешнего API.

## Столкновения

`collisions.rs` находит начало пересечения, двигаясь по возрастам обеих фигур.
Для встречного движения первой всегда передаётся обычная фигура, второй —
инвертированная, независимо от того, какая знает больше будущего.
`collision_rules.rs` получает эти значения и возвращает эффекты без мутации:

| Ситуация | Последствие из исходных правил |
| --- | --- |
| Свои, одно направление | Отменить последний ход вошедшей фигуры. |
| Свои, встречное движение, доска цвета фигуры | Погубить обычную фигуру. |
| Свои, встречное движение, доска другого цвета | Отменить ход инвертированной фигуры. |
| Противники, одно направление | Погубить фигуру, в которую вошли. |
| Противники, встречное движение | Обычно погибает обычная фигура. |
| Обычная фигура во встречном столкновении переместилась, зная будущее | Инвертированная погибает на столкновении; обычная — начиная со следующего собственного возраста. |

Гибель распространяется по **собственному возрасту**, а не обязательно в сторону
увеличения времени доски. Эффекты применяются отдельно от решения правила,
после чего проекции строятся заново.

## Оставшаяся работа по игровой механике

Восстановление после гибели пока использует занятость клетки первого мёртвого
состояния, а для en passant — запись породившего его хода. Для общих встречных
столкновений и каскадной взаимной гибели следует хранить явные причинные связи
захватов. Запомненные цели в `History` нужны для проверки ходов, но ещё не
являются полным графом причин гибели. Текущие тесты этих произвольных временных
сценариев не доказывают.

Отдельно остаются правила шаха через соседние времена, завершения партии,
пата и ничьих. Текущая фильтрация ходов проверяет безопасность всех королей
своего цвета на выбранной доске назначения. Вспомогательная проверка инвертированных
атак есть, но ещё не включена в полную временную проверку шаха.

## Изменения публичного API

- Вместо изменения полей `Engine` используются команды и неизменяемые снимки.
- Вместо `action_lines` используется `move_sources`: приоритета досок нет.
- Вместо трёх отдельных флагов доступности используется `MoveRights`.
- Вместо `to_past: bool` и трёх независимых `Option` используется направление
  `TimeDirection` и эффект `MoveEffect`.
- `State::step(direction)` меняет направление и временную идентичность;
  `State::prolongate` сохраняет направление. Оба возвращают `Option<State>`.
- `History::worldlines()` возвращает `&[Worldline]`; состояния читаются через
  срез, причинные разрывы — через `Worldline::gaps()`.
- `Board::pieces()` возвращает неизменяемый срез; индекс занятости закрыт.
- Базовые типы доступны через `model`; основные прежние импорты типов через
  `engine` и `pieces` сохранены как реэкспорты.

Тесты покрывают также ошибки индекса занятости после удаления, транспонирование
координат, безопасность короля, обязательность превращения, фактическое
перемещение ладьи при рокировке, откат при поздней ошибке согласования,
каскадную отмену ходов и восстановление после обычного взятия и en passant.
Для инверсии есть сценарии сохранения будущего, вложенных петель, точных границ
`loop_turn`, замены незавершённой и завершённой петли, отмены возврата,
взятия в прошлом и реакции на соседней доске. Смешанные последовательности
ходов дополнительно проверяют восстановление снимков и атомарность отказов.
