# Сетевой сервер Temporal Chess

Как в `capablanca-chess-plus-3d`: Actix Web + PostgreSQL, JSON по WebSocket,
сервер проверяет действия тем же Rust-движком, что и клиент. Один процесс сервера
обслуживает комнаты; несколько процессов требуют отдельного общего канала рассылки.

## Запуск

Создайте PostgreSQL-базу и пользователя, задайте `DATABASE_URL` (пример в корневом
`.env.example`). База должна быть отдельной от Capablanca: названия таблиц совпадают.

```sh
cp .env.example .env
# Отредактируйте DATABASE_URL под свою базу.
cargo run -p temporal-chess-server --release
```

Миграции применяются автоматически. `BIND_ADDR` по умолчанию `127.0.0.1:8080`.
Маршруты: `GET /health`, WebSocket `GET /ws`. Внешний HTTPS/WSS обслуживает Caddy.
Сервер не хранит фигуры, доски или мировые линии, присланные клиентами.

## Правила синхронизации

- Создатель выбирает белых, чёрных или случайную сторону. Другой игрок занимает
  оставшееся место по коду комнаты. Комната доступна сразу после создания.
- Место закреплено токеном, в БД хранится только SHA-256. Переподключение заменяет
  прежнее соединение этой стороны; прежний клиент больше не может отправлять ходы.
- `play_command` содержит ревизию и **одну строку формата NOLAN-CHESS 1**:
  `move`, `advance` или `continue`. Сервер проверяет очередь игрока, ревизию и
  допустимость действия. Бесконечный парадокс — штатное поражение, а не отказ сервера.
- Ревизия увеличивается после каждого принятого действия, даже если оно бесплатно
  или его ход исчез при пересчёте истории. Каждая принятая команда сохраняется в БД.
- При несовпадении ревизии сервер возвращает журнал целиком. Клиент восстанавливает
  начальную позицию и последовательно применяет команды. При обрыве связи команда
  не отправляется повторно вслепую: сначала восстанавливается серверная история.
- Сохранение, рассылка, снимки и замена соединений упорядочены внутри каждой комнаты.
  Дорогой пересчёт вынесен с async-потока на блокирующий пул.
- Ограничения: 10000 команд на комнату, 192 ASCII-байта на команду, 16 КиБ на входящее
  сообщение, 20 сообщений/сек на соединение. Есть heartbeat и ограниченные очереди.

Пример первого сообщения:

```json
{"type":"create_game","protocol":2,"side":"random","causal_gaps":false}
```

Клиент сохраняет токен автоматически: браузер — `localStorage`, нативный клиент —
`$XDG_DATA_HOME/nolan-chess/sessions` (по умолчанию `~/.local/share/nolan-chess/sessions`).
На Unix файлы новых токенов создаются с правами 0600. Код комнаты можно передавать
сопернику; токен предназначен только владельцу места. Токены привязаны к адресу сервера.
После перезапуска клиента введите прежний код комнаты. Вторая вкладка того же браузерного
профиля с тем же кодом восстанавливает ваше место; для второго игрока нужен другой профиль.

Локальный режим, экспорт и инспекция сохранены. Импорт, новая позиция и отмена хода
не меняют сетевую комнату: они доступны после выхода в локальный режим.

Режим комнаты задаётся `causal_gaps` при создании (обычно `false`), хранится
в PostgreSQL и передаётся обоим клиентам в `game_ready`. Протокол — версия 2.
Миграция 0002 сохраняет старые комнаты с `causal_gaps=true`.
